# Codex 3-Round Review - CSNL 3-Tier Orchestrator

## Round 1 - Design Soundness
1. **HIGH** - Boundary invariant is self-contradictory: the architecture says subagents never touch raw NAS (`docs/architecture-3tier-2026-05-13.md:19-24`), but Option B permits bounded direct NAS reads (`docs/architecture-3tier-2026-05-13.md:153-160`) while the kickoff forbids even `ls` (`docs/subagent-kickoff-template.md:26-29`); fix: remove Option B or move any emergency exception into a separately approved, audited procedure.
2. **MEDIUM** - `safe_memory.jsonl` can carry low-confidence material even though it is the orchestrator's only subagent input: the template permits `inferred`, `resolved_unknown`, and `new_unknown` lines (`docs/subagent-kickoff-template.md:173-180`), and the architecture says the orchestrator reads all seven safe-memory files (`docs/architecture-3tier-2026-05-13.md:13,132-135`); fix: split candidate memory from safe memory or enforce confirmed + confidence>=0.85 at writer side.
3. **HIGH** - JOP/SYJ protections depend on flags a cold-start session may omit: the template defines `hold=True` for JOP and `p4_active=True` for SYJ (`docs/subagent-kickoff-template.md:64-71`), but the migration prompt only says to include INIT-specific facts and flags (`docs/migration-prompt-2026-05-13.md:76-83`); fix: hard-code the current flag table in the cold-start prompt and require each subagent to echo received flags before work.
4. **MEDIUM** - Handoff timing is inconsistent: invariant 7 says each subagent posts handoff at session start (`docs/architecture-3tier-2026-05-13.md:25`), while the state schema and cadence say handoff is written and posted at session end (`docs/architecture-3tier-2026-05-13.md:112-114,144`); fix: define handoff as end-of-session output and make startup read/verify only.

## Round 2 - Concurrency and State
1. **HIGH** - Per-subagent state writes lack a lock or atomic-write contract: `context.md` append (`docs/subagent-kickoff-template.md:169-171`), `safe_memory.jsonl` append (`docs/subagent-kickoff-template.md:173-180`), and `dm_log.jsonl` append (`docs/subagent-kickoff-template.md:156-163`) are unprotected under concurrent reinvocation; fix: add a per-INIT state lock, use temp+rename for markdown, and use append+fsync for JSONL.
2. **MEDIUM** - `nas_runs/<UTC_ts>_<run_id>.jsonl` is not collision-proof because run-id generation and exclusive creation are unspecified (`docs/architecture-3tier-2026-05-13.md:102-103`, `docs/subagent-kickoff-template.md:100-105`, `docs/migration-prompt-2026-05-13.md:174-179`); fix: have the orchestrator assign UUID run ids and require exclusive-create output opens.
3. **LOW** - `fire_lock` uses cross-process `fcntl.flock`, which is suitable for cooperating local Python processes, but both examples open the lock file with `"w"` (`docs/subagent-kickoff-template.md:140-142`, `scripts/post_session_handoff.py:139-142`); fix: open with `a+` or `os.open` and reserve file contents for diagnostics.
4. **HIGH** - Handoff idempotency is racy and content-blind: `already_posted()` checks only `md_filename` (`scripts/post_session_handoff.py:63-76`) before the global lock is acquired (`scripts/post_session_handoff.py:129-145`), and the architecture permits append-only reuse of the same filename (`docs/architecture-3tier-2026-05-13.md:112-114`); fix: perform check+post+record under lock and key by filename plus content hash.

## Round 3 - Implementation Correctness
1. **HIGH** - The kickoff template still instructs subagents to spawn the Agent tool (`docs/subagent-kickoff-template.md:26-29,109-117`) despite the architecture noting that tool was not exposed and choosing orchestrator-side dispatch (`docs/architecture-3tier-2026-05-13.md:149-165`, `docs/migration-prompt-2026-05-13.md:85-93`); fix: rewrite the template to return a plan-ready signal for orchestrator dispatch.
2. **HIGH** - Hypothesis: the DM fire snippet is serialized but not atomic, because Slack post, ledger insert, and `dm_log` append run sequentially (`docs/subagent-kickoff-template.md:144-164`), so a crash after Slack success can lose ledger/log evidence; fix: add a durable outbox or intent row and reconcile by Slack ts.
3. **MEDIUM** - Discovery degrades for missing invites but hard-exits on `missing_scope` before writing any map (`scripts/discover_claude_channels.py:60-69`), while partial missing-channel handling writes a partial map (`scripts/discover_claude_channels.py:100-117`); fix: emit a structured failure artifact with missing scopes and any discoverable channels.
4. **MEDIUM** - Cold-start docs are stale: the architecture references `discover_claude_channels.mjs` (`docs/architecture-3tier-2026-05-13.md:89-90`) and the migration appendix says `.mjs` scripts are "TO BE WRITTEN" (`docs/migration-prompt-2026-05-13.md:130-134`), but the reviewed scripts are Python; fix: update names and status before using the migration prompt.
5. **MEDIUM** - `post_session_handoff.py` honors `fire_lock` per channel (`scripts/post_session_handoff.py:139-154`) but does not implement the documented first-post OK gate for new private channels (`docs/architecture-3tier-2026-05-13.md:201-205`); fix: require an explicit approval stamp or flag before first successful post per INIT.

## Consolidated Punch List
**HIGH:** remove/replace Option B direct NAS fallback; hard-code and echo JOP/SYJ flags; add per-INIT atomic state locking; move handoff idempotency under lock and hash content; rewrite subagent NAS dispatch instructions to Option A; make DM sends recoverable via outbox/reconciliation.

**MEDIUM:** split candidate vs safe memory or writer-gate confirmed facts; UUID/exclusive-create `nas_runs` outputs; resolve handoff timing; write structured discovery failure artifacts; fix stale `.mjs` references/status; enforce first-post OK gate.

**LOW:** open `fire_lock` without truncating it.
