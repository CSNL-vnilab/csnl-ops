# 보고서 2종 — 구조·문체 규약

두 문서는 **독자가 다르다.** 섞지 말 것.

| | 전문가활용 보고서 | 자문내용정리 |
|---|---|---|
| 독자 | 산학협력단 연구비 담당자 | 연구실 내부 + 감사 대비 근거자료 |
| 목적 | "이 돈이 왜 정당한가" 설명 | "실제로 무엇을 했는가" 증명 |
| 문체 | 격식 문어체, 서술형 문단 | 개조식 불릿 계층 |
| 기술 용어 | 최소화 (일반 담당자가 읽는다) | 허용 (구체적일수록 좋다) |
| 분량 | A4 1~2쪽 | A4 2~4쪽 |

---

## A. 전문가활용 보고서 (`전문가활용_<YYMMDD>`)

### 골격

```
              {제목} 활용
                 보고서

장소: {meeting.place}
활용일시: {YYYY년 M월 D일 오후 H시~H시 (총 N시간)}

1. 전문가 활용 목적
   {문단 1개, 5~8문장}

2. 회의 내용
   {문단 1개, 5~8문장}

3. 전문가 자문 결과
   {문단 1개, 5~8문장}

4. 향후 방안
   {문단 1개, 5~8문장}

[첨부목록 1 - 회의자료 예시]
[첨부목록 2 - 회의 사진]
```

### 문체 규칙

- **모든 절은 하나의 완결된 문단**으로 쓴다. 불릿 금지.
- 종결어미: `~하였다 / ~이다 / ~할 예정이다 / ~로 판단되었다`. 구어체·감탄·수사 금지.
- 논의 항목 열거는 `첫째, ~. 둘째, ~. 셋째, ~.` 문장 내 열거로 처리한다.
- **제품명·상표명·구체적 기술스택을 쓰지 않는다.** `Claude Code`→`인공지능 도구`, `Notion API`→`협업 플랫폼 연동`, `Vector DB`→`검색 기반 자료 구조`. 담당자가 특정 벤더 종속으로 오해할 여지를 없앤다.
- 금액·시간을 본문에서 반복하지 않는다(사용내역서와 불일치 위험).

### 절별 내용 배분

| 절 | 반드시 담을 것 |
|---|---|
| 1. 활용 목적 | 현재 연구실이 처한 문제 상황 → 그래서 왜 외부 전문가가 필요했는가 |
| 2. 회의 내용 | 실제 논의한 안건 3~4개를 `첫째~셋째` 형식으로. 역할 분담·우선순위도 언급 |
| 3. 자문 결과 | 자문으로 **확인/결정된 것**. "필요성이 확인되었다", "우선순위가 정리되었다" |
| 4. 향후 방안 | 단계별 계획(초기→중기→중장기)과 기대효과 |

### 예문 (톤 기준)

> 본 전문가는 연구실 내에 축적된 행동 및 신경 관련 자료를 체계적으로 관리하고 효율적으로 활용할 수 있는 기반을 마련하기 위하여 자문에 참여하였다. 현재 연구실에는 다양한 연구자료와 문서, 데이터 및 분석 산출물이 축적되어 있으나, 자료의 위치와 형식이 분산되어 있어 통합적 관리와 활용에 한계가 있는 상황이다.

## B. 자문내용정리 (`자문내용정리_<YYMMDD>`)

### 골격

```
1. 자문 개요
   ● 자문 건명: {한 줄, 구체적}
   ● 자문 위원: {이름} ({소속} / {전문분야})
   ● 참가자: {박준오 연구원, …}
   ● 자문 일정 및 형태:
       ○ 1차: {YYYY년 M월 D일} ({형태}, {N}분)
       ○ 2차: …

2. 일자별 상세 자문 내용
   ■ 1차 자문 ({날짜}): {그날의 한 줄 주제}
     ● {안건 제목}
         ○ {무엇을 어떻게 했는지 2~4문장}
     ● …
   ■ 2차 자문 …

3. 차기 자문 전 핵심 액션 아이템 (연구실 수행 계획)
   {한 줄 리드 문장}
   1. {과제명}
       ○ {완료 기준이 보이는 서술}
   2. …

[붙임 1-1. {도식 제목}]
```

### 규칙

- 불릿 계층은 `● → ○` 2단까지. 3단은 쓰지 않는다.
- **각 `●` 항목은 동사로 끝나는 명사구 제목**을 쓴다: "…파이프라인을 구축함", "…호환성 진단", "…설계".
- `○` 하위는 **완료형 종결**(`~함`, `~진행함`, `~식별함`)로 무엇이 실제로 일어났는지 쓴다.
- 기술 용어는 첫 등장 시 괄호로 풀어 쓴다: `NAS(네트워크 결합 스토리지)`, `WBS(업무 분할 구조도)`, `RAG(검색 증강 생성)`.
- 액션 아이템은 **연구실이 할 일**이다(전문가가 아니라). 차기 자문의 전제조건 형태로 쓴다.
- 녹취에 없는 항목을 만들지 않는다. 애매하면 인터뷰로 확인한다.

## 변환

마크다운 초안 → 최종물:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/build_report.py \
  --md draft/전문가활용_260403.md --out out/ --format docx pdf
```

- docx: 편집용 (본문 맑은 고딕 11pt, 제목 14pt bold)
- pdf: 제출용 (Chrome headless 인쇄)
- 파일명 규칙: `{문서종류}_{YYMMDD}.{ext}`, 지급 관련 파일만 `{전문가명}_` 접두.
